## Team Agreement

### Team Roles
- Product Owner - Adam Boyce
- SCRUM Master - Neel Kolhe
- Developers - Hunter Yates, Gerard Tibbles

### Rules of Conduct, Expectations, and Procedures
- Tell SCRUM master when we area absent if we aren't going to make it any planned meetings and email Matthew that when we are away.
- Use conventional commits
- Always pull before working
- Use the Rust Style Guide, https://doc.rust-lang.org/style-guide/
- Be respectful of each other and include each other in discussions as much as possible
- Bring up any potential issues that may arise to the product owner directly
- If you are not sure of the scope of what you are working on, get the product owner to clarify for you
- Rotate duties of taking meeting minutes
- SCRUM Master organises meetings and informs the team

### Team Goal
- To develop a working game, utlising the godot engine in the rust language
- We are aiming for an A+ grade in this class - 8 hours equvialent work each week per team member
- To get in using the Agile methodology in a project - specifically using SCRUM
- To learn new technologies that will benefit us in the future
- Develop and improve our collaborative practices

### Conflict Resolution process
- Raise issues with the SCRUM Master
- Any issues with the project itself raise with product owner
- Formal warning if conflict escalates - documented in writing. If neccessary SCRUM Master escalates to TA/Lecturer

### Breach of Conduct Consequences
- 5 push ups in the next lab
- number of push ups get raised to power of 2 if you breach for the same reason again
- Too many breaches, we will report to the TA/Lecturer
